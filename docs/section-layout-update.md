## セクションレイアウト調整メモ

### 概要
- 各主要セクション（Atlas Hero / Products / About / Careers / Contact）の縦幅をブラウザの表示領域（`100vh`）に合わせ、スナップスクロール時に画面と内容が正確に一致するように調整。
- ヘッダーを最前面に固定し、ヒーローセクション上に重ねることで、ヘッダー分の高さ差分（72px）が発生しないようにした。

### 実装内容
- 各セクションの高さ指定を `style={{ height: "calc(100vh - 72px)" }}` から `className="h-screen"` に変更し、親の `main` に対するスナップスクロールが 1 ビューポート単位で機能するようにした。
- `AboutSection` の背景画像に `h-full` を指定し、セクションの高さ変更後も余白なくカバーさせた。
- `main` コンテナで設定していた `scroll-padding-top:72px` を削除し、スナップ位置がヘッダー高さによって補正される状態を解消。
- `Header` の `z-index` を `z-[100]` に引き上げ、最前面で固定表示させることでヒーローセクション上に重ねて表示。

### この UI にした考え方
- **ビューポート単位の体験を優先**: フルスクリーンのセクション構成に合わせて、スクロール操作で常に 1 セクションが画面にフィットする体験を提供する。
- **ヘッダー位置の統一**: ヘッダーを最前面に重ねることで、各セクションで共通のスクロール基準を保ち、セクションごとの高さ調整を不要にした。
- **コンポーネントのシンプル化**: 可能な限り Tailwind のユーティリティクラスを使い、算術的な高さ指定を排除して保守性を高める。
- **視覚的な一貫性**: 背景画像や余白を `h-screen` に合わせて再調整し、セクション間の見た目のズレを防止。

### 今後の検討事項
- モバイル端末ではアドレスバーの表示状態によって `100vh` が変動するため、必要に応じて `svh` や JavaScript を使った補正を検討。
- ヘッダーの高さが変更された場合は、スナップ位置が再びずれないように `main` 側の調整を再確認する。
