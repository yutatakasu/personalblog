# 管理画面セットアップガイド

非エンジニアでも簡単にホームページのコンテンツを更新できる管理画面のセットアップ手順です。

## 1. Supabase 認証の設定

### 1.1 管理者アカウントの作成

1. Supabase Dashboard にアクセス
2. Authentication > Users を開く
3. "Add user" をクリック
4. メールアドレスとパスワードを設定
5. ユーザーを作成

**重要**: 管理者として設定するメールアドレスを記録しておいてください。

### 1.2 環境変数の設定

`.env.local` ファイルに管理者のメールアドレスを設定してください：

```env
# 管理者のメールアドレス（カンマ区切りで複数指定可能）
ADMIN_EMAILS=admin@atlas.inc,another-admin@atlas.inc
NEXT_PUBLIC_ADMIN_EMAILS=admin@atlas.inc,another-admin@atlas.inc
```

**注意**: 
- `ADMIN_EMAILS` はサーバー側で使用（`src/app/admin/layout.tsx`）
- `NEXT_PUBLIC_ADMIN_EMAILS` はクライアント側で使用（`src/components/admin/AdminLayout.tsx`、`src/app/admin/login/page.tsx`）
- 両方設定する必要があります

### 1.3 RLS ポリシーの設定

**重要**: 特定の管理者のみが書き込み可能になるように設定します。

1. Supabase Dashboard の SQL Editor を開く
2. `docs/supabase-admin-rls-strict.sql` を開く
3. `<YOUR_ADMIN_EMAIL>` を実際の管理者のメールアドレスに置き換える
4. 複数の管理者がいる場合は、OR条件で追加
5. SQL Editor で実行

**例**:
```sql
auth.jwt() ->> 'email' IN (
  'admin@atlas.inc',
  'another-admin@atlas.inc'
)
```

これにより、指定したメールアドレスのユーザーのみがデータの書き込み（作成・更新・削除）を行えるようになります。

## 2. 管理画面へのアクセス

1. 開発サーバーを起動：
   ```bash
   pnpm dev
   ```

2. ブラウザで `http://localhost:3000/admin/login` にアクセス

3. **管理者として設定したメールアドレス**でログイン

**注意**: 
- Supabase Dashboard で作成したすべてのユーザーがログインできるわけではありません
- 環境変数 `ADMIN_EMAILS` に設定したメールアドレスのユーザーのみが管理画面にアクセスできます
- また、RLSポリシーでも同じメールアドレスが設定されている必要があります

## 3. セキュリティの仕組み

### 3.1 二重チェック

1. **フロントエンド側のチェック**:
   - ログインページで管理者メールアドレスをチェック
   - 管理画面のレイアウトで管理者メールアドレスをチェック
   - 環境変数 `ADMIN_EMAILS` または `NEXT_PUBLIC_ADMIN_EMAILS` に設定されたメールアドレスのみアクセス可能

2. **データベース側のチェック（RLS）**:
   - Supabase の RLS ポリシーで、特定のメールアドレスのみが書き込み可能
   - フロントエンドのチェックをバイパスしても、データベース側でブロックされる

### 3.2 アクセス制御の流れ

```
1. ユーザーがログイン
   ↓
2. フロントエンドでメールアドレスをチェック
   ↓（管理者メールアドレスでない場合）
   → ログアウトしてエラーメッセージを表示
   ↓（管理者メールアドレスの場合）
3. 管理画面にアクセス
   ↓
4. データの書き込みを試みる
   ↓
5. RLSポリシーでメールアドレスをチェック
   ↓（管理者メールアドレスでない場合）
   → エラーを返す
   ↓（管理者メールアドレスの場合）
6. データの書き込みが成功
```

## 4. 管理画面の使い方

### 4.1 ニュース管理

1. サイドバーの「ニュース」をクリック
2. ニュース記事の一覧が表示されます
3. 「+ 新規作成」ボタンで新しい記事を追加
4. 各記事の「編集」ボタンで内容を変更
5. 「削除」ボタンで記事を削除
6. 「プレビュー」ボタンで実際のページを確認

#### ニュース記事の作成・編集

- **ID**: URLに使用されるID（英数字とハイフンのみ、編集時は変更不可）
- **タイトル**: 記事のタイトル
- **日付**: 表示形式（例: 2025.09.12）
- **タグ**: カテゴリ（例: Product Update, Partnership）
- **サムネイル画像URL**: 画像のパス（例: `/members_far_from.jpg`）
- **画像の説明**: アクセシビリティのための画像説明
- **リンク**: 記事の詳細ページへのリンク（例: `/news/atlas-os-v2-release`）
- **概要**: 記事の要約（オプション）

## 5. 画像のアップロード

現在は、画像を `public` フォルダに配置してから、そのパスを入力する必要があります。

### 画像アップロードの手順（現在）

1. 画像ファイルを `public` フォルダに配置
2. 管理画面で画像のパスを入力（例: `/image.jpg`）

### 今後の改善予定

Supabase Storage を使用した画像アップロード機能を実装予定です。これにより、管理画面から直接画像をアップロードできるようになります。

## 6. セキュリティに関する注意事項

### 6.1 パスワード管理

- 強力なパスワードを使用してください
- 定期的にパスワードを変更してください
- パスワードを他人と共有しないでください

### 6.2 アクセス制御

**現在の実装では、以下の2つのチェックでアクセスを制御しています：**

1. **環境変数によるチェック**:
   - `.env.local` の `ADMIN_EMAILS` と `NEXT_PUBLIC_ADMIN_EMAILS` に設定されたメールアドレスのみが管理画面にアクセス可能
   - この設定を変更するには、コードの変更と再デプロイが必要

2. **RLSポリシーによるチェック**:
   - Supabase の RLS ポリシーで、特定のメールアドレスのみが書き込み可能
   - この設定を変更するには、SQL Editor でポリシーを更新

**より厳格な権限管理が必要な場合は、以下の方法を検討してください：**

1. **ユーザーテーブルに管理者フラグを追加**
   - ユーザーテーブルを作成し、管理者フラグを追加
   - RLSポリシーで管理者フラグをチェック

2. **Supabase のカスタムロールを使用**
   - Supabase のロール機能を使用して、より細かい権限管理を実装

## 7. トラブルシューティング

### ログインできない

1. メールアドレスとパスワードが正しいか確認
2. Supabase Dashboard でユーザーが作成されているか確認
3. `.env.local` の `ADMIN_EMAILS` と `NEXT_PUBLIC_ADMIN_EMAILS` にメールアドレスが設定されているか確認
4. ブラウザのコンソールでエラーを確認

### 「アクセス権限がありません」と表示される

1. `.env.local` の `ADMIN_EMAILS` と `NEXT_PUBLIC_ADMIN_EMAILS` に、ログインしようとしているメールアドレスが含まれているか確認
2. `docs/supabase-admin-rls-strict.sql` のメールアドレスが正しく設定されているか確認
3. 環境変数を変更した場合は、開発サーバーを再起動

### データが保存できない

1. RLSポリシーが正しく設定されているか確認
2. `docs/supabase-admin-rls-strict.sql` を実行しているか確認
3. RLSポリシーのメールアドレスが、環境変数のメールアドレスと一致しているか確認
4. ブラウザのコンソールでエラーを確認

### 画像が表示されない

1. 画像のパスが正しいか確認（`/` で始まる必要があります）
2. 画像ファイルが `public` フォルダに存在するか確認
3. 画像ファイル名にスペースや特殊文字が含まれていないか確認
