# 管理画面セットアップガイド

非エンジニアでも簡単にホームページのコンテンツを更新できる管理画面のセットアップ手順です。

## 1. Supabase 認証の設定

### 1.1 管理者アカウントの作成

1. Supabase Dashboard にアクセス
2. Authentication > Users を開く
3. "Add user" をクリック（もしくは "Invite user" でメール招待）
4. メールアドレスを Google アカウントと一致させる
5. ユーザーを作成

**重要**: 管理者として許可したい Google アカウントのメールアドレスを登録してください。

### 1.2 管理者リストの設定

1. Supabase Dashboard の **SQL Editor** を開き、`supabase/sql/admin-users.sql` の内容を実行
   - `admin_users` テーブルと `is_admin_user` 関数が作成されます
2. Table Editor で `admin_users` テーブルを開き、管理者として許可するメールアドレスを追加
   - Google アカウントと完全一致（ケースは自動的に無視されますが、可能であれば小文字で登録）
   - 複数人いる場合は 1 行ずつメールアドレスを追加

> `admin_users` テーブルに登録されているメールアドレスのみが管理画面にアクセスできます。

### 1.3 RLS ポリシーの設定

**重要**: 特定の管理者のみが書き込み可能になるように設定します。

1. Supabase Dashboard の SQL Editor を開く
2. `supabase/sql/supabase-admin-rls-strict.sql` の内容を貼り付けて実行

これにより、`admin_users` テーブルに登録されたメールアドレスのユーザーのみが
データの書き込み（作成・更新・削除）を行えるようになります。

## 2. 管理画面へのアクセス

1. 開発サーバーを起動：

   ```bash
   pnpm dev
   ```

2. ブラウザで `http://localhost:3000/admin/login` にアクセス
3. **`admin_users` テーブルに登録したメールアドレスのユーザー**でログイン

**注意**:

- Supabase Dashboard でユーザーを作成しただけでは管理画面に入れません
- `admin_users` テーブルにメールアドレスを登録する必要があります
- RLS ポリシーも同じ条件で判定するため、テーブル登録は必須です

## 3. セキュリティの仕組み

### 3.1 二重チェック

1. **アプリケーション側のチェック**:

   - OAuth 認証完了後、Route Handler (`/admin/auth/callback/route.ts`) で `is_admin_user` RPC 関数を実行
   - `admin_users` テーブルにメールアドレスが登録されているか確認
   - 登録されていない場合はログアウトしてエラーメッセージを表示

2. **サーバー側レイアウトのチェック**:

   - `/admin/(protected)/layout.tsx` で `getUser()` を使用してユーザーを取得
   - `is_admin_user` RPC 関数で管理者権限を確認
   - 管理者でない場合は `/admin/login` にリダイレクト

3. **データベース側のチェック（RLS）**:
   - Supabase の RLS ポリシーで `is_admin_user(auth.jwt() ->> 'email')` を評価
   - フロントエンドのチェックをバイパスしても、データベース側でブロックされる

### 3.2 アクセス制御の流れ

```
1. ユーザーが Google OAuth でログイン
   ↓
2. Supabase が認証コードをセッションに交換（Route Handler）
   ↓
3. Route Handler で `is_admin_user` RPC を実行して管理者権限を確認
   ↓（`admin_users` に登録されていない場合）
   → ログアウトしてエラーメッセージを表示
   ↓（`admin_users` に登録がある場合）
4. Cookie にセッション情報を保存して `/admin/hub` にリダイレクト
   ↓
5. `/admin/(protected)/layout.tsx` で `getUser()` を使用してユーザーを取得
   ↓
6. `is_admin_user` RPC で再度管理者権限を確認
   ↓（管理者でない場合）
   → `/admin/login` にリダイレクト
   ↓（管理者の場合）
7. 管理画面を表示
   ↓
8. データの書き込みを試みる
   ↓
9. RLSポリシーで `is_admin_user(auth.jwt() ->> 'email')` を評価
   ↓（登録されていない場合）
   → エラーを返す
   ↓（登録されている場合）
10. データの書き込みが成功
```

### 3.3 技術的な実装詳細

- **認証フロー**: Route Handler (`route.ts`) を使用して Cookie にセッション情報を書き込む
- **セッション取得**: Server Component では `getUser()` を使用（`getSession()` は非推奨）
- **管理者判定**: `is_admin_user` SQL 関数を使用して `admin_users` テーブルをチェック
- **RLS ポリシー**: `is_admin_user(auth.jwt() ->> 'email')` で JWT からメールアドレスを取得して判定

## 4. 管理画面の使い方

### 4.1 ニュース管理

1. サイドバーの「ニュース」をクリック
2. ニュース記事の一覧が表示されます
3. 「+ 新規作成」ボタンで新しい記事を追加
4. 各記事の「編集」ボタンで内容を変更
5. 「削除」ボタンで記事を削除
6. 「プレビュー」ボタンで実際のページを確認

#### ニュース記事の作成・編集

- **ID**: URL に使用される ID（英数字とハイフンのみ、編集時は変更不可）
- **タイトル**: 記事のタイトル
- **日付**: 表示形式（例: 2025.09.12）
- **タグ**: カテゴリ（例: Product Update, Partnership）
- **サムネイル画像**: Supabase Storage（`news-photos`）へアップロード。16:9 でトリミング可能
- **本文段落**: テキスト + 任意の画像（各段落ごとに Supabase Storage へ保存）
- **画像の説明**: それぞれの画像に対するアクセシビリティテキスト
- **リンク**: 記事の詳細ページへのリンク（例: `/news/atlas-os-v2-release`）
- **概要**: 記事の要約（オプション）

## 5. 画像のアップロード

### ニュースセクション

- 管理画面から直接画像をアップロードできます
- サムネイル・本文内画像はいずれも Supabase Storage の `news-photos` バケットに保存されます
- サムネイルはアップロード時に 16:9 比率でトリミング可能
- 各段落ごとの画像も 16:9 比率でトリミング後に保存され、公開 URL が自動で設定されます
- バケット作成後は、`supabase/sql/storage-news-photos.sql` を実行して RLS ポリシー（管理者のみ書き込み可能）を適用してください

### その他のセクション

- 募集情報・チーム・サポーターなど、ニュース以外のフォームは引き続き `public` フォルダに画像を配置してパスを指定する運用です
- 手順:
  1. 画像ファイルを `public` フォルダに配置
  2. 管理画面で画像のパスを入力（例: `/image.jpg`）

## 6. セキュリティに関する注意事項

### 6.1 パスワード管理

- 強力なパスワードを使用してください
- 定期的にパスワードを変更してください
- パスワードを他人と共有しないでください

### 6.2 アクセス制御

**現在の実装では、以下の 3 つのチェックでアクセスを制御しています：**

1. **Route Handler でのチェック**:

   - OAuth 認証完了後、`/admin/auth/callback/route.ts` で `is_admin_user` RPC 関数を実行
   - `admin_users` テーブルに登録されたメールアドレスか確認
   - 管理者でない場合はログアウトしてエラーメッセージを表示

2. **サーバー側レイアウトでのチェック**:

   - `/admin/(protected)/layout.tsx` で `getUser()` を使用してユーザーを取得
   - `is_admin_user` RPC 関数で管理者権限を確認
   - 管理者でない場合は `/admin/login` にリダイレクト

3. **RLS ポリシーによるチェック**:
   - Supabase の RLS ポリシーで `is_admin_user(auth.jwt() ->> 'email')` を評価
   - フロントエンドのチェックをバイパスしても、データベース側でブロックされる
   - この設定を変更するには、SQL Editor でポリシーを更新

**管理者の追加・削除方法：**

- Supabase Dashboard の Table Editor から `admin_users` テーブルを開く
- メールアドレスを追加・削除するだけで権限を更新可能
- 変更後は、対象ユーザーが一度ログアウトしてから再ログインする必要があります

## 7. トラブルシューティング

### ログインできない

1. メールアドレスとパスワードが正しいか確認
2. Supabase Dashboard でユーザーが作成されているか確認
3. `admin_users` テーブルにメールアドレスが登録されているか確認
4. ブラウザのコンソールでエラーを確認

### 「アクセス権限がありません」と表示される

1. `admin_users` テーブルに対象メールアドレスが登録されているか確認
2. 登録後に再ログインして最新の JWT を取得
3. `supabase/sql/supabase-admin-rls-strict.sql` を実行して最新のポリシーになっているか確認

### データが保存できない

1. RLS ポリシーが正しく設定されているか確認
2. `supabase/sql/supabase-admin-rls-strict.sql` を再実行して最新の条件になっているか確認
3. `admin_users` テーブルにメールアドレスが登録されているか確認
4. ブラウザのコンソールでエラーを確認

### 画像が表示されない

1. ニュースの場合は、Supabase Storage の `news-photos` バケット内に該当ファイルが存在し、公開URLが取得できているか確認
2. その他のセクションは画像ファイルが `public` フォルダに配置されているか確認
3. 画像ファイル名にスペースや特殊文字が含まれていないか確認
