# 管理画面セットアップガイド

非エンジニアでも簡単にホームページのコンテンツを更新できる管理画面のセットアップ手順です。

## 1. Supabase 認証の設定

### 1.1 管理者アカウントの作成

1. Supabase Dashboard にアクセス
2. Authentication > Users を開く
3. "Add user" をクリック（もしくは "Invite user" でメール招待）
4. メールアドレスを Google アカウントと一致させる
5. ユーザーを作成

**重要**: 管理者として許可したい Google アカウントのメールアドレスを登録してください。

### 1.2 管理者リストの設定

1. Supabase Dashboard の **SQL Editor** を開き、`supabase/sql/admin-users.sql` の内容を実行
   - `admin_users` テーブルと `is_admin_user` 関数が作成されます
2. Table Editor で `admin_users` テーブルを開き、管理者として許可するメールアドレスを追加
   - Google アカウントと完全一致（ケースは自動的に無視されますが、可能であれば小文字で登録）
   - 複数人いる場合は1行ずつメールアドレスを追加

> `admin_users` テーブルに登録されているメールアドレスのみが管理画面にアクセスできます。

### 1.3 RLS ポリシーの設定

**重要**: 特定の管理者のみが書き込み可能になるように設定します。

1. Supabase Dashboard の SQL Editor を開く
2. `supabase/sql/supabase-admin-rls-strict.sql` の内容を貼り付けて実行

これにより、`admin_users` テーブルに登録されたメールアドレスのユーザーのみが
データの書き込み（作成・更新・削除）を行えるようになります。

## 2. 管理画面へのアクセス

1. 開発サーバーを起動：
   ```bash
   pnpm dev
   ```

2. ブラウザで `http://localhost:3000/admin/login` にアクセス
3. **`admin_users` テーブルに登録したメールアドレスのユーザー**でログイン

**注意**: 
- Supabase Dashboard でユーザーを作成しただけでは管理画面に入れません
- `admin_users` テーブルにメールアドレスを登録する必要があります
- RLS ポリシーも同じ条件で判定するため、テーブル登録は必須です

## 3. セキュリティの仕組み

### 3.1 二重チェック

1. **フロントエンド側のチェック**:
   - 認証完了後、Supabase セッションのメタデータを確認
   - `role: "admin"` / `roles` に `admin` / `is_admin: true` のいずれかがあれば許可

2. **データベース側のチェック（RLS）**:
   - Supabase の RLS ポリシーで、JWT メタデータに `admin` 権限が存在するかを検証
   - フロントエンドのチェックをバイパスしても、データベース側でブロックされる

### 3.2 アクセス制御の流れ

```
1. ユーザーがログイン
   ↓
2. フロントエンドで `is_admin_user` RPC を実行
   ↓（`admin_users` に登録されていない場合）
   → ログアウトしてエラーメッセージを表示
   ↓（`admin_users` に登録がある場合）
3. 管理画面にアクセス
   ↓
4. データの書き込みを試みる
   ↓
5. RLSポリシーで `admin_users` テーブルをチェック
   ↓（登録されていない場合）
   → エラーを返す
   ↓（登録されている場合）
6. データの書き込みが成功
```

## 4. 管理画面の使い方

### 4.1 ニュース管理

1. サイドバーの「ニュース」をクリック
2. ニュース記事の一覧が表示されます
3. 「+ 新規作成」ボタンで新しい記事を追加
4. 各記事の「編集」ボタンで内容を変更
5. 「削除」ボタンで記事を削除
6. 「プレビュー」ボタンで実際のページを確認

#### ニュース記事の作成・編集

- **ID**: URLに使用されるID（英数字とハイフンのみ、編集時は変更不可）
- **タイトル**: 記事のタイトル
- **日付**: 表示形式（例: 2025.09.12）
- **タグ**: カテゴリ（例: Product Update, Partnership）
- **サムネイル画像URL**: 画像のパス（例: `/members_far_from.jpg`）
- **画像の説明**: アクセシビリティのための画像説明
- **リンク**: 記事の詳細ページへのリンク（例: `/news/atlas-os-v2-release`）
- **概要**: 記事の要約（オプション）

## 5. 画像のアップロード

現在は、画像を `public` フォルダに配置してから、そのパスを入力する必要があります。

### 画像アップロードの手順（現在）

1. 画像ファイルを `public` フォルダに配置
2. 管理画面で画像のパスを入力（例: `/image.jpg`）

### 今後の改善予定

Supabase Storage を使用した画像アップロード機能を実装予定です。これにより、管理画面から直接画像をアップロードできるようになります。

## 6. セキュリティに関する注意事項

### 6.1 パスワード管理

- 強力なパスワードを使用してください
- 定期的にパスワードを変更してください
- パスワードを他人と共有しないでください

### 6.2 アクセス制御

**現在の実装では、以下の2つのチェックでアクセスを制御しています：**

1. **`admin_users` テーブルによるチェック**:
   - Supabase の RPC で `admin_users` に登録されたメールアドレスか確認
   - Table Editor からメールアドレスを追加・削除するだけで権限を更新可能

2. **RLSポリシーによるチェック**:
   - Supabase の RLS ポリシーで `is_admin_user(auth.jwt() ->> 'email')` を評価
   - この設定を変更するには、SQL Editor でポリシーを更新

**より厳格な権限管理が必要な場合は、以下の方法を検討してください：**

1. **ユーザーテーブルに管理者フラグを追加**
   - ユーザーテーブルを作成し、管理者フラグを追加
   - RLSポリシーで管理者フラグをチェック

2. **Supabase のカスタムロールを使用**
   - Supabase のロール機能を使用して、より細かい権限管理を実装

## 7. トラブルシューティング

### ログインできない

1. メールアドレスとパスワードが正しいか確認
2. Supabase Dashboard でユーザーが作成されているか確認
3. `admin_users` テーブルにメールアドレスが登録されているか確認
4. ブラウザのコンソールでエラーを確認

### 「アクセス権限がありません」と表示される

1. `admin_users` テーブルに対象メールアドレスが登録されているか確認
2. 登録後に再ログインして最新の JWT を取得
3. `supabase/sql/supabase-admin-rls-strict.sql` を実行して最新のポリシーになっているか確認

### データが保存できない

1. RLSポリシーが正しく設定されているか確認
2. `supabase/sql/supabase-admin-rls-strict.sql` を再実行して最新の条件になっているか確認
3. `admin_users` テーブルにメールアドレスが登録されているか確認
4. ブラウザのコンソールでエラーを確認

### 画像が表示されない

1. 画像のパスが正しいか確認（`/` で始まる必要があります）
2. 画像ファイルが `public` フォルダに存在するか確認
3. 画像ファイル名にスペースや特殊文字が含まれていないか確認
