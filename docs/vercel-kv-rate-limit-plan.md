# Vercel KV を用いたログインレート制限リニューアル計画

## 目的

- ブルートフォース攻撃対策をメールアドレス単位で安定運用するため、サーバーレス環境でも状態が共有されるレート制限ストアを導入する。
- 現状のメモリベース実装を置き換え、Vercel KV（Redis 互換）で永続化する。

## スコープ

- 対象ルート: `/admin/login/start`, `/admin/auth/callback`, `/api/admin/login/rate-limit`
- 対象モジュール: `src/lib/security/login-rate-limit.ts`
- 環境: Vercel（Production / Preview / Development）

## 要件

1. **共有ストア**

   - すべての Vercel Edge/Serverless 関数から同一の KV にアクセスできること。
   - メールアドレス単位のキーで試行回数とブロック期限を管理する。

2. **性能要件**

   - 1 回のレート制限判定で最大 2 回の KV アクセス（読み取り + 書き込み）に抑える。
   - KV の無料枠（読み取り 10,000 / 書き込み 1,000 / 日）を意識し、不要なアクセスは避ける。

3. **フォールバック**

   - KV が利用不可の場合は安全側に倒す（ログイン不可）。
     - ユーザーに「現在ログインを受け付けていません」と表示。
     - `console.error` で検知可能にする。

4. **運用**
   - KV のキーは `login-rate-limit:{email}` 形式で保管。
   - TTL を付与（例: 2 時間）し、自然にクリーンアップされるようにする。

## 実装ステップ

1. **セットアップ**

   - `@vercel/kv` を dependencies に追加。
   - Vercel Project Settings に以下の環境変数を設定し、`vercel link` / `vercel env pull` で共有。
     - `KV_REST_API_URL`
     - `KV_REST_API_TOKEN`
     - `KV_URL`（オプションだが SDK 初期化で使用）

2. **KV クライアントモジュール**

   - `src/lib/kv/client.ts`（仮称）を追加し、`VercelKV` インスタンスを初期化。
   - エラー時は `null` を返し、呼び出し側でフォールバック処理を行う。

3. **レート制限モジュールのリファクタ**

   - `login-rate-limit.ts` のデータアクセスを KV へ置き換え。
   - メモリストアはローカル開発のフォールバックとして残す。
   - KV への読み書きは `JSON.stringify` / `JSON.parse` で行う。
   - TTL を `EX` オプションで設定。

4. **ルートの更新**

   - `/admin/login/start`: KV がブロック状態なら即座にリダイレクト。
   - `/admin/auth/callback`: 認証失敗時は `recordLoginFailureByEmail` を KV 経由で呼び出し。
   - 成功時は `resetEmailRateLimit` を KV で削除。

5. **テスト**
   - 単体テスト（可能なら Vitest を導入）で KV モジュールをモック。
   - 開発環境では `edge-config` や dotenv を使い、KV が無い場合も想定。
   - 手動テスト:
     1. 同アカウントで 5 回失敗 → ブロック
     2. 30 分待たず再試行 → ブロック継続
     3. 1 時間後に解除されるか確認
     4. 成功ログイン後にカウントがリセットされるか確認

## ロールアウト計画

1. `feature/vercel-kv-rate-limit` ブランチで開発。
2. Preview で KV を設定し、QA ログイン試験を実施。
3. 本番環境へデプロイ。デプロイ前に KV の統計/アラートを設定。
4. 1 週間モニタリング後、メモリベース実装を削除するクリーンアップを検討。

## リスクと対策

| リスク      | 影響                                     | 対策                                                                              |
| ----------- | ---------------------------------------- | --------------------------------------------------------------------------------- |
| KV がダウン | ログインできない                         | フォールバックメッセージと監視ログを用意                                          |
| 無料枠超過  | KV 書き込み失敗でログインできない        | 失敗ログを計測し、必要に応じて有料プランへ切り替え                                |
| 競合状態    | ダブルカウントや書き戻しタイミングのずれ | `INCR` / `EVAL` 的な原子的操作を検討、または `SET` with `NX` と Lua Script の採用 |
